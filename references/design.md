# 设计原理

## 1. 文档过期 ≠ 文档老

判定标准是"**承重断言是否还可验证**"，不是时间。三年前的 ADR 可能完全有效，三天前的部署步骤可能已经致命。

因此体系只需做三件事：

1. 让失效**可被脚本发现**（元数据 + 校验）；
2. 让更新**有明确触发**（代码变更、时间、使用情况）；
3. 让处置**有默认动作**（确认 / 更新 / 归档）。

## 2. 四层分级

| 层级 | 文档 | 失效后果 | 复核周期 | 更新触发 |
|---|---|---|---|---|
| T1 | runbook、发布/回滚、安全、数据修复 | 直接故障 | 30–90 天 | 系统或流程变更 |
| T2 | 模块契约、API 用法、数据模型、配置 | 改错地方、返工 | 90–180 天 | 对应代码变更 |
| T3 | 规格、术语、架构全景、愿景 | 方向跑偏 | 180 天 / 每版本 | 需求或架构变更 |
| T4 | ADR、事故复盘 | 误导决策 | 不复核 | 只被新 ADR 取代 |

统一"半年一查"是错的：T1 太松，T4 太严。分级是整套规则的地基。

## 3. 三种历史，三种载体

| 历史 | 回答什么 | 载体 | 产生新文件 |
|---|---|---|---|
| 编辑历史 | 谁在何时改了哪些字 | git | 否 |
| 语义历史 | 含义经历过哪些变化 | 文末 `## 变更记录` | 否 |
| 版本历史 | 某时点的完整承诺快照 | 独立文件 + archive | 是 |

最常见的错误：用"另存为副本"解决编辑历史需求，于是出现 `deploy-v2-final.md`，多份都有人看、都在烂。

**判定**：纠错/补充 → 原地改；承诺/合规/对外契约 → 版本化。

## 4. 状态机

```
draft → active → stale → deprecated → archived
            ↑_______|   （复核后可复活）
```

- `active`：已验证，可信，索引与搜索正常。
- `stale`：可能过时，黄色横幅 + 搜索降权，进入复核队列。
- `deprecated`：有替代品，红色横幅 + 替代链接。
- `archived`：冻结、只读、移出索引与搜索，保留 URL。

状态是数据，不是记忆。渲染、搜索、CI 全部读 front-matter。

## 5. 三种更新驱动

### 变更驱动（挡住 80% 腐化）

`docs.map.yaml` 显式声明代码路径 → 文档。PR 中 sources 变了而 docs 没变就失败。
把"更新文档"从道德要求变成合并前置条件。允许 `docs-not-needed` 标签加理由，但理由要接受审计。

### 时间驱动（兜住剩余部分）

`last_reviewed + review_interval_days` 算出到期项，按 owner 聚合成 issue。复核不是重读，是**验证**：跑 `verified_by`、校 3 条承重断言、三选一处置。

### 使用驱动（决定去留）

零访问 + 零入链 6 个月 → 归档候选；高访问 + 长期 stale → 最高优先级修复（有人在依赖过期信息）。

## 6. 归档

- 移动而非删除，保留原相对路径：`docs/archive/<年份>/<原路径>`。
- tombstone 元数据：`archived_at`、`archived_reason`、`superseded_by`、`retain_until`。
- 只读：CI 阻止修改；从 index 移除；在 `archive/README.md` 登记。
- 保留期：合规 7 年、技术 2 年、一次性 90 天。到期季度清理。

归档区膨胀到几百份时检索价值归零——**删除是维护手段，不是失败**。

## 7. 度量

| 指标 | 目标 |
|---|---|
| T1/T2 新鲜率 | ≥ 90% |
| 漂移违规数 | 逐月下降 |
| 孤儿文档率（无 owner/无入链） | < 5% |
| 逾期天数中位数 | < 15 天 |
| 复核后 30 天内被证伪比例 | < 5% |

不要用文档总数、字数、提交次数考核——只会换来灌水。

## 8. 反模式

| 反模式 | 后果 |
|---|---|
| 运动式全量重写 | 之后照旧腐烂 |
| 只靠提醒，无 CI 阻塞 | 等于没有规则 |
| 复核直接点"确认" | 给旧内容续命 |
| 舍不得删 | 索引信噪比下降，agent 捡到过期内容 |
| 高漂移文档远离代码 | 改代码的人看不到，永不更新 |
| 文档里链接 `blob/main` | 随代码演进静默失效，应用 tag 永久链接 |
| 内部文档套 semver + 多版本站 | 每次修错字都像发版，最终无人维护 |

## 9. 一句话

历史交给 git，语义交给变更记录，承诺交给快照，废弃交给归档，归档交给索引和保留期。
